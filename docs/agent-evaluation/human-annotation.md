# 人工标注方案（用于校准 LLM 评委）

> 人工标注的目的**不是**用人来给 agent 排名，而是回答一个问题：**LLM 评委的分数能不能信？** 所以设计重点是：样本覆盖好坏两端、盲评、先测人与人的一致性，再拿评委去比。

## 1. 样本：36 份，分层抽取

| 类别 | 数量 | 作用 |
|---|---|---|
| agent 生成的论文 | 12 题 × 2–3 个配置 ≈ 28 | 主体 |
| 真人获奖论文 | 4（O 奖 / Finalist 2 篇，Honorable Mention / Successful Participant 2 篇） | **外部锚点**：人和评委都应该给出 O 奖 > HM > SP 的顺序，否则是评分标准有问题 |
| 植入缺陷的论文 | 2–4（拿好论文改掉关键数值、删掉一个小问、加一个错误假设） | 注意力检查 + 测评委能否发现硬伤 |

- 题目选不同领域（连续/离散/数据驱动/评价类），配置尽量拉开质量差距，避免 36 份都挤在中间分数段。
- 另留 3 份做**试标**，不进入正式统计。

## 2. 标注人

- 3 人，有数模竞赛经历（参赛过至少一次国赛/美赛），你可以是其中一人。
- **每份论文 2 人独立打分**，其中 10 份 3 人全标，用于算一致性。工作量：约 36×2+10 ≈ 82 次；每篇 20–30 分钟，每人约 10–12 小时，建议分 3–4 次完成。
- 标注人 ID 匿名化；如有报酬按小时计，不按分数计。

## 3. 盲评

- 去掉 agent 名称、模型名、文件路径、运行日志等一切身份信息，文件名用随机 ID。
- **格式泄露问题**：MathModelAgent 的 Typst 模板一眼能认出来。处理办法：
  - 内容维度（分析、建模、结果）在**统一渲染的 Markdown/HTML 版本**上打分；
  - 单独一个"排版与表达"维度看原始 PDF。
- 每位标注人的阅读顺序随机打乱。

## 4. 打分表

### 4.1 二元检查项（一致性最高，先做）
每项填 是 / 否 / 不适用，并写页码或章节作为证据：
1. 每个小问都有明确答案
2. 假设列出且合理
3. 模型与小问目标对应（不是套模板）
4. 使用了题目给的数据
5. 做了灵敏度分析或误差分析
6. 做了模型检验（交叉验证、回测、与已知结果比较等）
7. 关键数值合理（量级、单位、符号）
8. 发现事实性错误或编造内容（有则写明位置）

### 4.2 维度打分（1–5 分，每档有锚点描述）
与 MM-Bench 四维对齐，外加表达维度：

| 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| 问题分析 | 误解题意或漏掉小问 | 理解正确但拆解浅 | 抓住核心矛盾，拆解清楚且有取舍理由 |
| 建模严谨性 | 模型与问题不对应或推导错误 | 标准模型直接套用，假设部分合理 | 假设—模型—求解链条完整，有针对性改进 |
| 实用与科学性 | 结论无法落地或与常识冲突 | 有结论但缺乏解释 | 结论可操作，解释了适用范围 |
| 结果与偏差分析 | 无检验、无灵敏度 | 有但流于形式 | 系统分析误差来源并影响结论 |
| 排版与表达 | 结构混乱、图表缺失 | 可读 | 可直接提交的水准 |

最后再给一个**总体分（1–7）**和一句话理由。用 1–5 而不是 1–10：档位少，锚点才写得清楚，一致性更高。

> 评分标准要先试标再定稿，锚点最好各配一个真实论文片段作为例子。

### 4.3 成对比较（可选，但推荐）
同一题下随机配对两份论文："哪一份更好？A / B / 差不多"。成对判断比绝对分更稳定，用来检验评委的成对比较能力。每人约 15 对，每对 5 分钟。

## 5. 流程

1. **写初版评分标准**（你来写，1 天）。
2. **试标会**：3 人独立标同样 3 份试标论文 → 一起对分歧最大的地方逐条讨论 → 修改锚点描述。重复直到主要维度的分差基本 ≤1。
3. **正式标注**：独立完成，期间不讨论，不看评委分数。
4. **裁决**：同一份论文两人某维度相差 ≥2 分时，由第三人裁决。**一致性统计使用裁决前的原始分**，裁决后的分数作为"金标准"。
5. 结束后收一份简短反馈：哪些维度最难判断。

## 6. 工具

| 方案 | 适合 |
|---|---|
| Google 表单 / 共享表格 + PDF 链接 | 最快启动，36 份完全够用 |
| [Label Studio](https://labelstud.io/)（开源，自托管） | 需要在网页里并排看论文和打分表 |
| 自写 Streamlit 标注页（左侧论文、右侧打分表，写入 JSONL） | **推荐做进作品里**，约 1 天工作量，可与 dashboard 共用代码 |

数据格式（一行一次标注）：

```json
{"paper_id": "p_7f3a", "annotator": "A2", "round": "formal",
 "checks": {"all_subq_answered": "yes", "sensitivity": "no", "...": "..."},
 "evidence": {"sensitivity": "未找到相关章节"},
 "scores": {"analysis": 4, "rigor": 3, "practicality": 3, "validation": 2, "presentation": 4},
 "overall": 4, "rationale": "...", "minutes_spent": 24}
```

## 7. 分析

1. **人与人一致性（天花板）**：每个维度算 Krippendorff α（序数型）。≥0.8 好，0.67–0.8 可接受，<0.67 说明该维度定义不清 → 改标准或剔除，不要要求评委在这种维度上做得比人好。
2. **评委与人一致性**：评委分 vs 人工金标准的 Spearman ρ；二元检查项用 Cohen's κ；成对比较用与人类多数意见的一致率。**关键对比**：评委—人的一致性 ≥ 人—人一致性时，才说评委可替代人工。
3. **锚点检查**：人和评委是否都给出 O 奖 > HM > SP；植入的缺陷有多少被发现。
4. **偏差检查**：长度偏差（字数与分数的相关）、位置偏差（成对比较交换 A/B）、自我偏好（评委与被测 agent 同一厂商时是否偏高）。
5. **防止过拟合评委**：用 12 份调评委 prompt，另外 24 份只做最终测试，不回头改 prompt。

## 8. 注意事项

- 获奖论文与赛题版权属于主办方：只在内部标注使用，仓库里只放编号与下载链接。
- 标注数据公开前去掉标注人信息。
- 如果找不到 3 个人：2 人全标 36 份也能算 α，只是没有第三人裁决，改用两人讨论后达成一致的分数作为金标准。
