# 行为感知的组合库协同进化：设计基线

> 状态：当前推荐方案（working design）  
> 最近更新：2026-08-21  
> 适用范围：LLM4AD 上的 destroy–repair 双种群协同进化  
> 关联材料：[跨领域调研](./literature-review.md)｜[原实施方案](./implementation-plan.md)｜[Stage 0/0.5 结果](./experiments/RESULTS.md)｜[Stage 0.5 复核](./stage05-review-and-next-steps.md)

本文记录 Stage 0、Stage 0.5 与跨领域调研汇合后的当前设计，作为后续实现、实验和论文叙事的共同基线。它不替代实验原始记录，也不改写已经完成的结论；它主要回答：**距离、变异坍缩与信用分配应如何共同进入协同进化闭环。**

若本文与原实施方案的 Stage 2–5 冲突，以本文记录的当前优先级为准；原实施方案中的 LLM4AD 架构分析、可重放环境要求和测试床选择仍然有效。

## 1. 当前结论

建议把研究主线定义为：

> **行为感知的组合库协同进化（behavior-aware portfolio coevolution）**：
> 协同进化的目标不是找到累计奖励最高的单个算子或算子对，而是让 destroy 与 repair 两个种群共同扩张一组不可替代、可组合的求解能力。

对应的三个研究问题不是三个并列模块，而是一条因果链：

```text
LLM 变异趋向相似
      ↓
行为有效维度坍缩 ──→ 句法/embedding 距离可能看不见
      ↓
近似克隆瓜分或累积信用，专才和新算子被误杀
      ↓
种群进一步集中，下一代继续从坍缩区域采样
```

因此，当前最重要的设计判断是：

1. **行为距离是仪表和调度工具**，用于识别克隆、构造伙伴覆盖和发现能力缺口。
2. **组合库边际贡献是进化信用**，用于奖励“不可替代的能力”，而不是被选择次数。
3. **行为缺口驱动的生成是变异干预**，用于确保候选池本身能离开已有吸引子。
4. `γ` 保留为交互诊断量和条件分支，不再作为默认主线。

## 2. 已有证据与解释边界

| 证据 | 已确认事实 | 对当前设计的含义 |
|---|---|---|
| Stage 0 E1 | 累加式 `S_ij` 主要测到 `α_i + β_j`，而非真正交互 `γ_ij` | 不用 `argmax S` 声称发现了协同 |
| Stage 0 E2 | 自适应利用降低配对覆盖率，进而损害交互估计 | 把在线求解、评估调度和进化选择分成三套目标 |
| Stage 0 E3 | 85 分位新算子在累加式信用下误杀率高达 94% | 新算子必须有最低评估配额、收缩估计与不确定性保护 |
| Stage 0.5 | 经典算子、单步 payoff 下可以排除较大的 `γ` | `γ` 不足以支撑默认主线 |
| Stage 0.5 复核 | repair 有效自由度只有 1.29/6（CVRP）和 1.49/6（VRPTW） | 上述 `γ` 结论不能外推到行为多样的专才或 LLM 演化算子 |
| 跨领域调研 | 句法差异不可靠地代表行为差异；边际贡献可以自动抑制克隆膨胀 | 核心度量应从代码空间移动到探针行为与能力足迹 |

解释边界：当前证据支持“现有信用和距离可能驱动/掩盖坍缩”，但尚未证明“改用边际信用一定提高最终求解性能”。这正是后续闭环实验要检验的因果命题。

## 3. 三个问题的操作性答案

这一节直接回答三个问题各自“怎么处理”。三个问题保留各自独立的研究假设和判定实验，不因为统一进同一个系统就合并成一个含混的大问题。

| 问题 | 要得到的答案 | 推荐处理 | 第一个判定实验 |
|---|---|---|---|
| #1 信用分配 | 一个算子的能力是否来自自身，而非采样次数、伙伴运气或短期收益 | 平衡取证 → 收缩主效应 → 组合库边际信用 → 后期反事实时序信用 | 固定同一批真实观测，重放不同剪枝规则 |
| #2 变异退化为相似 | LLM 变异是否持续回到已有行为模式，以及能否主动离开 | 变异链审计 → 缺口驱动生成 → 多候选行为筛选 → 停滞时宏变异/重启 | 固定 LLM 预算比较普通变异与行为引导变异 |
| #3 算子距离 | 哪种距离真正对应 held-out 行为差异，而非代码表面差异 | 分层 probe bank → 角色特定签名 → 噪声校准距离 → 独立验证 | L0/L1/L2 对 held-out 行为矩阵的预测审计 |

依赖关系是：**#3 先造尺子，#2 用尺子诊断并引导生成，#1 决定哪些差异值得存活。** 信用分配的基础版本可以先运行，但行为分层伙伴、克隆诊断和缺口驱动生成必须等距离通过验证门禁。

### 3.1 问题 #1：信用分配怎么处理

#### 研究问题

> 在伙伴质量、采样频率、搜索阶段和新算子样本量都不均衡时，怎样估计一个 destroy/repair 对最终求解能力的真实贡献？

这里实际包含三种信用，不能再用一个 `F += σ` 混在一起：

| 层 | 要回答的问题 | 输出 |
|---|---|---|
| 单次评价信用 | 这次轨迹或步骤带来了多少收益？ | 标准化 `u(d,r,c)` |
| 个体能力信用 | 排除伙伴和上下文后，这个算子自身是否有能力？ | 收缩后的 `α_d` / `β_r` 与不确定性 |
| 进化存活信用 | 把它从当前组合库移走，会失去多少不可替代能力？ | LOO/MC-Shapley `φ` |

#### 处理流程

**第一步：先保证取证公平。** 每个新算子至少与以下伙伴评价：

1. 一个固定 anchor，保证跨代可比；
2. 对侧每个主要行为簇的代表，降低伙伴混淆；
3. 一个当前最欠采样或不确定性最高的伙伴；
4. 相同上下文比较使用共同随机数。

候选达到最低证据量之前不得硬剪枝。MVP 可从“`1` 个 anchor + `3` 个行为簇代表、每个组合 `3` 个 CRN 上下文”起步，即至少 `12` 条可比 rollout；这个数是工程起点，正式阈值由方差 pilot 决定。

**第二步：估计基础能力而不是累计奖励。** 在账本上拟合带上下文效应和收缩的模型：

```text
u(d,r,c) = μ_c + α_d + β_r + γ_dr + ε
```

- `μ_c` 吸收实例、搜索阶段和残解难度；
- `α/β` 是基础能力，用于冷启动、在线选择先验和置信区间；
- `γ` 只作诊断，不默认驱动选择；
- 新算子向全局或行为邻域先验收缩，证据增加后再逐渐摆脱先验；
- 若行为先验没有在 held-out 数据上达到预注册相关性，则只向全局均值收缩。

**第三步：用组合库边际贡献决定存活。** 固定另一个种群，比较加入/移除某算子前后的 `V(D,R)`。先用 LOO 打通管线，再用截断 MC-Shapley处理相关算子组。全局 elite 单独保护，避免组合库目标因上下文覆盖不足而丢掉绝对强者。

**第四步：最后再解决时序信用。** 基础版本使用按实例和搜索阶段归一化的轨迹终值；可重放环境稳定后，再在关键步骤替换实际算子为 anchor 算子：

```text
credit_t = G(original_trajectory) - G(counterfactual_replay_t)
```

分别替换 destroy 和 repair，即可得到比单步改进更接近因果效应的局部信用。RUDDER/SeqAU 是重放过贵时的近似对照，而不是一开始的必需组件。

#### 判定实验

先做一个**离线剪枝重放实验**，不要立刻跑完整 LLM 闭环：

1. 用经典算子、专才算子和若干人为近克隆组成固定候选池；
2. 在完整均衡的 `(context, destroy, repair)` 网格上取数；
3. 按真实时间顺序逐步释放观测，模拟在线不均衡数据；
4. 分别用累加、均值、收缩 `α/β`、LOO 和 MC-Shapley 做每轮剪枝；
5. 用完整网格的 held-out 组合库价值作为“谁不应被剪掉”的真值。

主指标：高价值新算子误杀率、信用与 held-out 边际价值的 Spearman、置信区间覆盖率、最终保留组合库的 `V`、行为有效自由度。

建议预注册的成功门槛：

- 相对累加基线，新算子误杀率至少下降 50%；
- 信用与 held-out 边际价值的相关显著高于均值/累加；
- 在相同种群容量下，组合库 `V` 不低于基线，同时有效自由度更高；
- 增加近克隆数量时，该行为簇获得的总信用不随克隆数线性膨胀。

#### 失败后怎么走

- `α/β` 不稳定：优先增加 anchor/分层伙伴覆盖，不先加复杂模型；
- Shapley 提高多样性但降低 `V`：说明上下文或组合库价值定义错了，而不是多样性越大越好；
- LOO 把一个有价值的克隆簇全部记成零：切换 MC-Shapley 或先按行为簇分组分配信用；
- 反事实重放结果高度不稳定：检查状态/RNG 是否真正可重放，再谈时序模型。

### 3.2 问题 #2：变异退化为相似怎么处理

#### 研究问题

> LLM 变异是否是行为空间中的收缩映射；若是，哪一种生成干预能以固定 LLM 预算持续产生新的、有用的行为？

必须先把“生成不出来”和“生成出来但被选择淘汰”分开。前者是变异问题，后者是信用/选择问题。

#### 先做变异链审计

冻结 selection，不根据 fitness 淘汰，单独运行多条变异链：

```text
parent_0 → child_1 → child_2 → ... → child_T
```

固定模型、prompt 模板、温度、调用预算和起始父代分层，逐代记录：

- AST/embedding/探针行为到父代和历史档案的距离；
- 行为有效自由度、最近邻距离和历史行为重访率；
- 自环/短环比例；
- 参数微调、控制流改变、数据结构改变等编辑类型；
- 合法率、性能和对组合库价值的预测边际增益。

若代码距离维持甚至上升、行为距离却下降，就是“换皮式坍缩”；若候选行为有差异但存活后坍缩，主因在信用/选择而非生成。

#### 四级干预

**M1：多候选生成。** 一次要求 LLM 给出 `k≈5` 个机制不同的方案、各自假设和预期作用上下文，再从中筛选。自报概率只用于促进枚举，不作为真实 propensity。

**M2：双约束变异。** prompt 同时指定：

- 保留父代中已验证有效的核心机制；
- 必须改变一个会影响探针行为的结构性决策；
- 行为要超过同一算子重复运行产生的噪声半径；
- 优先远离当前档案最密集区域，而不是无条件追求最大距离。

**M3：能力缺口驱动。** 从 L3 足迹中找当前组合库最弱的 `(实例类型, 搜索阶段, 残解簇)`，把该缺口、失败轨迹和已有近邻机制明确提供给 LLM。候选排序看预测 `ΔV`，不是只看 novelty。

**M4：停滞逃逸。** 当连续若干代行为最近邻距离和 `ΔV` 都低于阈值时，触发宏变异、跨岛父代、经典机制注入或从空白重新设计；不要继续在同一父代上增加温度碰运气。

#### 候选接受规则

候选依次通过四道门：

1. 接口、复杂度、确定性和安全性检查；
2. 精确/AST 近重复过滤；
3. L2 行为差异超过基于重复测量得到的噪声下界；
4. 在验证 probe 上有正的预测边际价值，或因高不确定性获得有限探索配额。

“离档案很远”不能单独成为接收理由。无效但怪异的算子应在第 4 道门被挡住。

#### 判定实验

先在冻结选择的变异链上比较：

| arm | 改动 |
|---|---|
| M0 | 当前单候选变异 |
| M1 | verbalized multi-candidate |
| M2 | M1 + 近父代/远档案双约束 |
| M3 | M2 + 能力缺口驱动 |
| M4 | M3 + 停滞逃逸 |

所有 arm 固定总 LLM 调用数和完整评估数。主指标不是文本差异，而是：每次 LLM 调用产生的独特行为数、行为重访率、有效自由度斜率、正 `ΔV` 候选率和最佳性能。

进入闭环前建议要求：

- 独特行为产出率至少为 M0 的 1.5 倍；
- 行为重访率显著下降；
- 正 `ΔV` 候选率没有因追求 novelty 而下降；
- 提升在 held-out probe/实例上仍成立。

之后再用“普通/行为引导变异 × 累加/边际信用”的 2×2 实验判断：坍缩来自生成、选择，还是两者正反馈。

#### 失败后怎么走

- L0/L1 变远但 L2 不变：prompt 仍在做表面编辑，强制控制流/数据结构级宏变异；
- L2 变远但 `ΔV≈0`：探针捕获的是无用差异，升级 L3 足迹或 interestingness gate；
- M1 无收益：模型枚举的仍是同一模式，改为多父代/多岛或显式互斥机制模板；
- 生成阶段多样、选择后坍缩：停止优化 prompt，优先修信用和存活规则。

### 3.3 问题 #3：算子距离怎么处理

#### 研究问题

> 哪个可计算距离能稳定区分“行为上相同的换皮算子”和“代码相似但能力互补的算子”，并预测 held-out 搜索行为？

距离不是寻找一个万能公式，而是建立一把经过信度和效度检验的尺子。

#### Probe bank 怎么建

probe 必须覆盖算子真实会遇到的状态分布，而不是只取随机初始解：

| 维度 | 初始分层建议 |
|---|---|
| 问题 | CVRP、VRPTW 分开建库 |
| 实例 | 规模、聚类程度、容量/时间窗紧度 |
| 搜索阶段 | `0 / 50 / 200 / 1000` 深度的 incumbent |
| 破坏强度 | 至少小/中/大三档 |
| 随机性 | 同一算子重复种子，用来估计行为噪声半径 |

起步可各取约 `128` 个状态，按来源分成 calibration 与 held-out 两半；数量最终由签名稳定性曲线决定，不把 `128` 当论文常数。

destroy 和 repair 使用不同输入：

- destroy 在共同完整解上运行，记录其产生的残解；
- repair 在共同标准残解上运行，这些残解由多个 destroy 类型和强度生成；
- repair 之间必须看到完全相同的残解和随机流，避免把输入差异误当算子差异。

#### 签名与距离怎么计算

每个算子的原始响应先变成定长签名 `b(o)`。连续特征按 probe 内稳健尺度标准化，集合/序列特征使用 Jaccard、秩距离或轨迹统计，再拼接成角色特定向量。

MVP 同时保留两个 L2 距离：

```text
d_corr(o1,o2)  = 1 - corr(b(o1), b(o2))
d_white(o1,o2) = sqrt((b1-b2)^T W (b1-b2))
```

其中 `W` 根据同一算子重复运行的方差降权高噪声特征。若算子本身是随机策略，则比较响应分布，可用 energy distance/Wasserstein，而不是只比较一次运行的点估计。

距离阈值不手填固定常数。先测“同一个算子、不同种子”的距离分布，把其 95% 分位作为噪声下界；候选只有显著超过这个下界才算行为不同。

#### 三层验证

**信度：这把尺子是否稳定。**

- 同一算子重复测量的距离应显著小于不同算子；
- probe 子采样后距离排序应稳定；
- 建议门禁：test–retest ICC `≥ 0.8`。

**区分效度：是否能识别已知相同/不同。**

- 阴性对照：重命名、等价重构、参数微扰；
- 阳性对照：segment/scatter destroy、segment/independent repair 等机制差异明确的算子；
- L2 应将等价重构判近、将阳性对照判远。

**预测效度：是否对应真正有用的行为。**

- calibration probes 计算 L0/L1/L2；
- 完全独立的实例和搜索轨迹形成 held-out L3 能力足迹；
- 比较各距离与 held-out 行为差异的 Spearman/Mantel 一致性；
- 建议门禁：L2 的相关 `≥ 0.5`，且 bootstrap 下显著优于 L0/L1。

未同时通过信度与预测效度的距离，只能作为分析图，不能进入选择、聚类或 prompt。

#### 距离通过后怎么用

按风险从低到高依次启用：

1. 只做跨代仪表盘和近克隆报警；
2. 用于选择行为簇代表，改善伙伴覆盖；
3. 用于子代与最近行为邻居局部竞争；
4. 用于缺口驱动 prompt 和候选筛选；
5. 最后才尝试 sharing/DPP 等直接改变存活的机制。

这种递进可以区分“距离测得准”和“把距离放进算法后真的有用”两个命题。

#### 失败后怎么走

- test–retest 不稳定：增加重复、去掉高噪声特征或改为分布距离；
- 能区分经典算子但不能预测 held-out 足迹：probe 状态分布不对，补搜索后期和困难残解；
- L2 与 L1 一样弱：检查签名是否只记录粗粒度终值，应加入决策序列和残解结构；
- repair 全部仍然很近：这可能是真实的算子集退化，应换入专才，而不是强行调整距离制造差异。

### 3.4 实际执行顺序与近期产物

不要同时实现完整协同进化。建议按下列顺序逐个消除不确定性：

| 顺序 | 任务 | 产物 | 决定什么 |
|---:|---|---|---|
| 1 | 修复/专才算子与阳性对照 | 扩展后的 Stage 0.5 审计 | 测量流水线是否能看见已知差异 |
| 2 | L0/L1/L2 距离审计 | `distance_validity_audit.py` + 报告 | #3 的尺子能否使用 |
| 3 | 冻结选择的变异链审计 | `mutation_collapse_audit.py` + 报告 | #2 是否发生、发生在哪一层 |
| 4 | 离线信用/剪枝重放 | `credit_replay_ablation.py` + 报告 | #1 哪种信用更接近 held-out 价值 |
| 5 | 2×2 小规模闭环 | 普通/行为变异 × 累加/边际信用 | 三个问题如何在闭环中互相影响 |
| 6 | 完整 `method/coevo` | 可恢复的双种群实验 | 最终性能和论文主结论 |

到第 4 步为止都不需要把所有模块塞进 LLM4AD method；只有距离、变异和信用分别通过各自门禁后，才进入完整闭环实现。

一句话操作指南：

> **先用独立 held-out 行为验证距离；再用距离证明并干预变异坍缩；最后用组合库边际价值决定这些差异是否值得获得信用。**

## 4. 三层闭环：不要让一个奖励承担三个任务

当前方法常用同一个单步奖励 `σ` 同时更新在线权重、累计适应度和配对分数。这三个用途的目标并不一致，应拆成三个闭环：

```text
┌──────────────────────────────────────────────────────┐
│ 外层：协同进化                                      │
│ 目标：扩大组合库的不可替代能力；决定生成、存活与亲本 │
└──────────────────────┬───────────────────────────────┘
                       ↓
┌──────────────────────────────────────────────────────┐
│ 中层：评估调度                                      │
│ 目标：公平估计；anchor + 行为分层伙伴 + 欠覆盖上下文 │
└──────────────────────┬───────────────────────────────┘
                       ↓
┌──────────────────────────────────────────────────────┐
│ 内层：LNS 求解                                      │
│ 目标：当前预算内求出更好解；允许自适应利用          │
└──────────────────────┬───────────────────────────────┘
                       ↓
       可重放轨迹 → 信用账本 → 估计 → 外层更新
```

三层分别使用不同信号：

| 用途 | 推荐信号 | 不应直接使用 |
|---|---|---|
| LNS 在线选算子 | 条件期望收益/UCB/Thompson | 组合库 Shapley 信用 |
| 评估采样 | 覆盖率、估计不确定性、分层伙伴 | 纯即时奖励最大化 |
| 进化存活与亲本选择 | 组合库边际贡献 + 基础能力 + 冷启动保护 | 累加式 `F += σ` |

## 5. 核心对象与数据定义

### 5.1 上下文

把一次评价所在的环境记作：

```text
c = (problem, instance, search_phase, residual_cluster, seed)
```

- `search_phase` 至少区分早期、改进期、局部最优附近；
- `residual_cluster` 描述 destroy 产生的残解结构；
- 同一比较区组使用共同随机数（CRN）；
- 训练/调度上下文与最终验证上下文严格分离。

### 5.2 配对效用

一次 destroy–repair 配对的效用记作 `u(d, r, c)`。初期可使用按实例和搜索阶段归一化的轨迹终值或相对改进；后期再用精确重放、RUDDER 或 SeqAU 处理延迟信用。

原始单步奖励必须保留，但它只是账本中的观测，不直接等同于进化适应度。

### 5.3 行为签名

每个算子保存版本化的探针行为签名：

- destroy：移除指示、移除规模、空间/时间跨度、路线归属熵、残解结构和可行性破坏程度；
- repair：在标准残解上的插入顺序、候选位置排名、贪心/后悔痕迹、重排行为和修复轨迹；
- L0 AST 与 L1 embedding 只作为廉价预过滤，L2 探针行为作为核心距离；
- L3 实例 × 搜索阶段能力足迹用于衡量“有用的多样性”。

有效自由度使用行为响应相关矩阵的参与比：

```text
effective_dimension = (Σ λ_i)² / Σ λ_i²
```

它是跨代坍缩的主仪表盘，而不是独立优化目标。

### 5.4 跨种群兼容性

destroy 与 repair 不是同一种对象，不能简单用两个 embedding 的欧氏距离表示兼容性：

- destroy 表示残解分布 `P(partial_solution | d)`；
- repair 表示对残解的响应函数 `utility(r, partial_solution)`。

兼容性应定义为：

```text
compat(d, r) = E_{s^- ~ P(·|d)}[utility(r, s^-)]
```

若要研究纯交互，再从该量中减去 destroy/repair 主效应；不要把未经中心化的配对总收益称为协同。

## 6. 组合库价值与进化信用

### 6.1 组合库价值

首先使用性能足迹定义组合库价值，避免一开始把显式多样性奖励混入核心实验：

```text
V(D, R) = Σ_c w_c · max_{d∈D, r∈R} u(d, r, c)
```

这个 facility-location 式目标衡量当前双种群能覆盖多少求解上下文。它会奖励通才，也会奖励在少数上下文中不可替代的专才。

`max` 表示组合库的能力上界。若实际求解时的算子选择器不能接近这个上界，应另报告“由固定选择策略实现的 V”，避免把 oracle 能力误报为真实 solver 性能。

### 6.2 角色条件边际信用

固定当前 repair 种群，为 destroy 分配信用：

```text
φ_d = E_{S⊆D\{d}}[V(S∪{d}, R) - V(S, R)]
```

固定当前 destroy 种群，为 repair 分配信用：

```text
φ_r = E_{T⊆R\{r}}[V(D, T∪{r}) - V(D, T)]
```

两个种群在代际边界交替重算信用。这仍是协同信用：一个算子的价值始终以另一个种群当前能提供的伙伴为条件。

实现顺序：

1. leave-one-out：便宜，用于打通管线；
2. 贪心边际增益：直接用于固定容量的组合库选择；
3. 截断 Monte Carlo Shapley：主实验，公平处理相关算子组；
4. sharing 与 DPP：作为独立 ablation，验证显式多样性项是否还有额外收益。

近似克隆在 Shapley 下会瓜分同一份能力价值，而不是每个克隆都拿满；与 leave-one-out 不同，Shapley 也不会因为多个克隆互相替代而把整个有价值的行为簇全部记成零。

### 6.3 存活和亲本选择

不要把所有量立即线性加成一个脆弱的标量。初期采用：

- 至少保留一个全局性能 elite；
- 其余位置按对 `V` 的贪心边际增益构造组合库；
- 行为近邻之间做局部竞争，避免一个行为簇占满容量；
- 新算子获得最低跨伙伴评估配额，在置信度不足前不参与硬剪枝；
- `α/β` 收缩估计作为基础能力和冷启动信号，而非最终唯一适应度。

## 7. 伙伴评估策略

每个新 destroy 或 repair 至少接受三类评价：

1. **anchor partner**：固定经典基线，保证跨代可比；
2. **stratified partners**：从对侧行为簇各取代表，降低伙伴混淆；
3. **informative partners**：针对当前欠覆盖或后验方差大的上下文补样。

评估调度不等于 LNS 在线选择。在线 solver 可以利用高收益组合；进化评价必须保留足够覆盖，否则无法判断一个候选只是碰到了坏伙伴，还是自身确实无效。

纯 `γ-UCB` 暂不作为默认调度器。只有在修复算子集、阳性对照和搜索深度扫描均通过后，真实交互达到预注册门槛，才恢复为条件实验臂。

## 8. 行为缺口驱动的 LLM 变异

每轮生成从“当前组合库缺什么”开始，而不是从“当前谁分数最高”开始：

1. 从 L3 能力足迹中找表现最弱或不确定性最高的上下文；
2. 选择与该缺口相关、但仍有基础能力的父代或父代对；
3. 要求 LLM 一次产生 `k` 个机制不同的候选及其设计假设；
4. 约束候选在行为上“接近父代但远离档案”；
5. 先做合法性、AST 近重复与廉价探针过滤；
6. 按预测边际增益和不确定性选择少量候选做完整评估。

LLM 自报概率只用于促使其显式枚举分布，不作为真实选择概率，也不用于 IPS。

联合生成遵循：

> **pair 是提案单位，operator 是信用和存活单位。**

可以针对同一个残解缺口联合生成 destroy 与 repair，以获得 prompt 推理和接口一致性收益；生成后必须拆开，与多个 anchor 和多样化伙伴交叉评估，避免把一次偶然配对永久固化成不可解释的 pair genome。

## 9. 一代协同进化的推荐流程

```text
输入：D_g, R_g, 行为档案 A_g, 账本 L_g

1. 从能力足迹中选择未覆盖上下文 c*
2. 分别或联合生成 destroy/repair 候选集
3. 用 L0/L1 过滤换皮代码，用 L2 探针筛选行为候选
4. 为每个候选分配 anchor + 分层 + informative partners
5. 在 CRN 下执行可重放 LNS，记录完整轨迹
6. 按实例和搜索阶段归一化配对效用 u(d,r,c)
7. 用收缩 α/β 更新基础能力与不确定性
8. 计算角色条件的 LOO/MC-Shapley 边际信用
9. 以 elite + 贪心组合库边际增益更新 D_{g+1}, R_{g+1}
10. 更新行为档案、有效自由度曲线、血缘和编辑级统计
```

后期加入精确反事实时，只替换第 6 步的信用输入，不改变整个进化控制器。

## 10. LLM4AD 实现边界

建议新建一个同步双种群 method，而不是长期依赖两个异步 EoH 实例：

```text
llm4ad/task/optimization/cvrp_lns/
├── state.py          # 解、残解和序列化状态
├── operators.py      # 算子接口契约与经典基线
├── rollout.py        # 确定性 LNS、轨迹与重放
├── probes.py         # 探针库和行为签名
└── evaluation.py     # 纯执行，返回结构化 RolloutBatch

llm4ad/method/coevo/
├── coevo.py          # 双种群同步控制器
├── population.py     # 个体、组合库与代际更新
├── scheduler.py      # 伙伴/上下文评估调度
├── credit.py         # mean、ANOVA、LOO、Shapley、sharing、DPP
├── behavior.py       # 距离、聚类、有效自由度和行为档案
├── ledger.py         # SQLite 账本与版本化快照
├── prompt.py         # 缺口驱动、verbalized sampling、联合生成
├── replay.py         # 反事实重放与时序信用
└── lineage.py        # 血缘、编辑标签和跨代信用
```

职责边界：

- `Evaluation` 子进程只执行确定性 rollout，返回可序列化记录；
- 主进程 `coevo` 控制器写账本、计算信用并更新种群；
- 原始观测与派生信用分开保存，任何新估计器都能从账本重算；
- 每条记录至少包含 `run_id, generation, operator_ids, context_id, state_hash, seed, selection_probability, raw_rewards, final_return, accepted`；
- 探针集、归一化器、信用算法和组合库快照都要带版本号。

## 11. 修订后的阶段路线

### Stage 1：环境、探针与测量门禁

- 建成可精确重放的 CVRP LNS；
- 固化 destroy/repair 接口；
- 建立按搜索阶段分层的 probe bank；
- 删除近重复 repair，加入专才算子；
- 加入设计上必然存在交互的 2×2 阳性对照。

门禁：

- repair 有效自由度 `≥ 3`；
- 阳性对照 `γ` 占比 `> 25%` 且置换检验 `p < 0.01`；
- 相同状态、种子和调用序列能够逐步重放。

### Stage 2：距离有效性审计

在相互独立的 probe/validation 数据上比较：

- L0：AST/token 距离；
- L1：代码 embedding；
- L1+：LLM 逻辑相似性判断；
- L2：探针行为距离。

主检验：这些距离对 held-out 行为差异和 L3 能力足迹差异的 Spearman/Mantel 一致性。严禁用同一响应矩阵同时构造距离和充当验证真值。

### Stage 3：记账层协同进化

固定生成策略、伙伴预算和随机种子，仅替换进化信用：

| arm | 信用方案 | 目的 |
|---|---|---|
| C0 | 四级 `σ` 累加 | 复现基线 |
| C1 | 频率去偏均值 | 分离被选次数效应 |
| C2 | 收缩 `α/β` | 基础能力与冷启动 |
| C3 | leave-one-out 组合库边际 | 廉价边际信用 |
| C4 | MC-Shapley | 公平处理相关行为簇 |
| C5 | C4 + sharing 或 DPP | 检查显式多样性项的额外价值 |

核心因果命题：在完全相同的变异候选下，仅改变记账方式，是否就能减缓有效自由度下降。

### Stage 4：行为引导变异

在最优记账方案上加入：

- verbalized sampling；
- “近父代、远档案”的双约束；
- 行为缺口驱动的 parent/context 选择；
- 必要时加入 LLM interestingness gate。

用 2×2 因子实验分离信用机制与变异机制：

| | 普通变异 | 行为引导变异 |
|---|---|---|
| 累加信用 | 基线 | 只改变变异层 |
| 边际信用 | 只改变记账层 | 完整方法 |

### Stage 5：时序和因果信用

- 从按阶段归一化的轨迹终值开始；
- 比较极值统计、RUDDER/SeqAU 与精确重放 difference reward；
- 只在高不确定性或接近剪枝边界的决策点做昂贵重放；
- 用 global-local alignment 和信用守恒作为独立正确性指标。

### 条件分支：真实交互与 `γ`

专才算子集和搜索深度扫描完成后再决定：

| 条件 | 决策 |
|---|---|
| `γ* > 15%`，或随深度单调上升且末端 `> 10%` | 恢复 `γ-UCB + 定向覆盖` 实验 |
| `5% ≤ γ* ≤ 15%` | `γ` 作为次要机制，主线仍是边际信用与行为多样性 |
| `γ* < 5%` 且阳性对照通过 | 不投入 `γ` 控制器，保留为机制归因结论 |
| 阳性对照失败 | 停止解释真实数据，先修测量流水线 |

## 12. 评价指标与公平比较

所有闭环实验固定 LLM 调用数、候选数、CPU 评估预算、实例划分和随机种子。至少报告：

### 求解质量

- final best objective/gap；
- anytime performance/AUC；
- 跨实例排名与置信区间。

### 行为多样性

- destroy/repair 有效自由度随代数的曲线；
- 行为最近邻距离、近克隆比例；
- L3 能力足迹覆盖率；
- 代码多样性与行为多样性的偏离程度。

### 信用质量

- 新算子误杀率；
- 信用与 held-out 边际价值/global return 的 alignment；
- 置信区间覆盖率和达到稳定排序所需样本数；
- 同一行为簇获得的总信用是否随克隆数量膨胀。

### 成本

- LLM 调用数和 token；
- rollout/反事实重放次数；
- 每一代墙钟时间与账本规模。

“有效自由度提高”本身不能代替性能结果；目标是维持**有用的多样性**，因此必须同时给出求解质量与 L3 能力覆盖。

## 13. 关键风险与防护

1. **循环验证**：用同一探针响应定义 L2 距离又证明 L2 与行为一致。  
   防护：probe、调度和 held-out validation 三套数据分离。

2. **把新颖当价值**：行为很远但始终无效的算子占满种群。  
   防护：进化信用以性能边际贡献为主，距离只负责去重、调度和生成目标。

3. **伙伴混淆**：候选因偶遇糟糕伙伴被错误剪枝。  
   防护：anchor + 行为分层伙伴 + 收缩估计 + 最低评估配额。

4. **Shapley 成本失控**：双种群联合子集空间过大。  
   防护：角色条件计算、截断 Monte Carlo、行为簇分组，只对剪枝边界个体加密估计。

5. **探针随代漂移**：跨代距离与有效自由度不可比。  
   防护：固定核心 probe bank，新增探针只形成新版本并保留旧版本回算。

6. **oracle portfolio 夸大真实性能**：`max` 能力上界无法被在线选择器实现。  
   防护：同时报告 oracle `V` 与固定选择器实现的 `V_policy`。

7. **一次加入太多机制**：无法判断收益来源。  
   防护：先做记账层单变量实验，再加入行为引导变异，最后加入时序/因果信用。

## 14. 当前决策清单

### 已接受，进入实现基线

- 维持 destroy/repair 两个独立种群；
- 使用自定义同步 `coevo` method；
- 可重放 LNS 和事件账本是地基；
- L2 行为探针早于完整协同进化实现；
- 有效自由度作为跨代坍缩仪表盘；
- 进化信用从累计奖励转向组合库边际贡献；
- 在线选择、评估调度和进化存活使用不同目标；
- 联合生成后拆开组件进行交叉评估；
- `γ` 降级为条件分支。

### 需要实验决定

- 组合库价值采用 oracle `max`、固定 selector，还是两者同时使用；
- LOO 是否足够，还是必须使用 MC-Shapley；
- 行为签名的最小特征集和 probe 数量；
- sharing 与 DPP 是否在性能边际信用之上仍有收益；
- RUDDER、SeqAU 与精确重放的成本—收益关系；
- LLM 直接 interestingness 判断是否优于纯 L2 阈值。

### 暂不投入

- 直接按 `argmax S_ij` 做联合交叉；
- 在当前退化 repair 集上优化 `γ` 估计器；
- 把 embedding 距离作为核心多样性指标；
- 把 LLM 自报概率当真实 propensity；
- 在未验证先验相关性前投入复杂的语义冷启动模型。
